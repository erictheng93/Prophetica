建立 24/7 客服體系，處理玩家一般查詢、KYC 異議、結算申訴、責任博弈個案、技術故障。

4. 客服權限分級

角色 可執行操作
T1 查詢用戶資訊（去 PII）、回覆工單、調整單筆設定
T2 解凍帳戶、KYC 重啟、回覆爭議、執行 RG 個案
T3 帳本調整提案（需 4-eye）、代表平台對外溝通、SAR 提交
Admin 配置 FAQ、調整客服系統設定
Compliance 結算 reversal、SAR 簽核、監管溝通

工程師不直接處理客服工單。技術問題由客服轉至 Engineering team backlog。

5. 客服查詢介面

5.1 玩家檔案頁面

客服可查（須留稽核 log）：

  • 基本資訊（去除身份證號等 PII，僅 hash 後 4 碼）
  • KYC tier 與歷史
  • 儲值 / 交易 / 結算紀錄
  • RG 評分歷史
  • 最近 30 日工單

5.2 不可直接看的資訊

資訊 取得方式
證件影像 透過 Compliance 申請 + 主管簽核
完整身份證號 同上
完整信用卡號 不可取得（PCI DSS）
完整密碼 hash 不可取得

5.3 操作日誌

每筆客服操作（查詢、修改、回覆）寫入 audit_logs，包含：

  • 操作員 user_id
  • 目標 user_id
  • 操作類型
  • 操作前後資料（修改類）
  • 工單關聯 id
  • 時間戳、IP、User-Agent

6.2 玩家主動求助

  • Help Center 顯著位置「責任博弈協助」入口
  • 客服有專屬腳本與培訓
  • 提供合作戒癮機構聯繫資訊
  • 不嘗試「挽留」玩家，遵循 player-first 原則

6.3 親友通報

  • 接受第三方通報，但不可直接以親友通報為據停權
  • 通報觸發系統 review，通報內容不對玩家揭露
  • 客服可在後續 RG 評估中參考
  • 確認問題嚴重 → 客服聯繫玩家，邀請其自我排除

7. 結算申訴處理

呼應 SPEC-004 §5（申訴窗口）：

7.1 客服分流

  • 玩家提交申訴 → 工單分類為 dispute
  • T2（Compliance 組）優先處理
  • 24 小時申訴期內所有申訴必須回覆狀態（即使尚未裁決）

7.2 客服範本回應

  • 我們已收到您的申訴，將於 24 hr 內進行裁決
  • 裁決過程中我們將參考所有持倉者意見
  • 裁決結果為最終，但您可申請進一步審查（升級 T3）

7.3 升級到 Compliance

  • 案件涉及金額 > USD 1,000 → 直接升級
  • 案件涉及多人申訴 → 直接升級
  • T2 無法判定 → 升級

8. 工具與系統

8.1 推薦工單系統

  • Zendesk 或 Freshdesk（成熟、整合強）
  • 自建：Linode 上的 OS Ticket / RT（成本低但維護高）

決策：MVP 用 Zendesk，DAU > 100k 後評估遷移。

8.2 Live Chat

  • Intercom 或 Crisp
  • 整合 user context（自動帶入 user_id、KYC tier）

8.3 知識庫

  • 整合於 Zendesk
  • 內容由客服 + 法務協作維護
  • 多語：繁中、簡中、英文、日文（首發）

11. 客服系統與帳本整合

當客服執行影響帳本的操作（如：退款、補償、扣回）：

  • 不直接寫入帳本
  • 透過 compensation API 提案，需 4-eye 簽核（T3 + Compliance）
  • 帳本變動寫入 Txn type = 'cs_compensation'，附工單 id 為 correlation
