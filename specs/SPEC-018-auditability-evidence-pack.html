SPEC-018 — 稽核與合規證據化（Auditability & Evidence Pack）

優先級：P1（Public Beta Launch Gate） 版本：v0.1.0 · 最後更新：2026-05-09 依賴：SPEC-002, SPEC-004, SPEC-010, SPEC-011, SPEC-012, SPEC-016 被依賴：法遵、內控、監管稽核流程

v0.1.0

  • 新增「可出證據化」作為平台第一級控制目標：帳本動作、風控判定、客服稽核都需可追溯。
  • 新增證據匯出作業（Evidence Pack）框架，並將欄位細節、表結構、加密與保存策略放到 implementation plan。

1. Objective

確保平台每一筆關鍵動作都可回溯到可驗證的證據，支持法規詢問、帳務稽核、爭議調解與內部稽核抽查。

2. 範圍

  • 交易與帳本事件留痕（deposit、trade、commission、refund、reversal）
  • 風控決策留痕（AML/KYC/RG/referral/risk flags）
  • 客服與操作留痕（查詢、調整、工單與 4-eye）
  • 支付對帳證據（webhook、對帳差異、修正）
  • 法遵輸出（Evidence Pack）

3. 行為規格（產品可讀）

3.1 不可變更紀錄原則

  • 所有高風險動作必須具備「不可刪除」留痕（append-only）。
  • 任何留痕需保留：操作者、時間、目的、前後狀態、關聯參照、審核鏈。
  • 同一事件不得重複記錄；重試與重放須可區分。

3.2 關鍵操作與留痕邊界

  • 帳本相關：入帳、出帳、對帳、reversal、補償、退票。
  • 風控相關：人工放行、封鎖、解除、review 結果、機器判斷結果。
  • 客服相關：查詢、狀態變更、審核意見、溝通模板。
  • 支付相關：webhook 原始 payload、驗簽紀錄、重放標記、對帳結果。

3.3 監管調查模式

  • 在調查期間，證據需可匯出為只讀套件，包含事件時間軸與關聯事件樹。
  • 調查套件必須可按案例編號、用戶、工單、交易與時間窗查找。
  • 導出的資料不得含未脫敏之 PII，必要欄位以授權機制分級。

3.4 保留政策

  • 交易、帳本、風控與客服留痕需長期保存，不可因用戶刪除申請刪除。
  • 證據原文（webhook/event）需有不可竄改封存策略。
  • 保留年限、異地備援與銷毀政策由 implementation plan 指定。

4. 導出能力

  • 案例式 Evidence Pack：輸出「時間軸 + 原始事件鏈 + 事件摘要」。
  • 定期稽核報表：按日/週/月產生監管可讀匯總。
  • 帳本對帳證據：由結帳區間、事件、對帳差異、補償記錄三者交叉對照。

本規格不列出欄位、schema 或加密流程，implementation plan 需定義資料表、封存與導出格式。

6. 驗收條件（產品）

  • [ ] 高風險事件可按角色、交易、時間窗查到完整不可刪除軌跡
  • [ ] Evidence Pack 能在不暴露敏感資訊前提下完整匯出
  • [ ] 支付 webhook 重放與實際入帳結果可建立一一對應
  • [ ] 客服與風控的 4-eye 或多階段核准可回溯
