## 1. Objective

確保 propheticaNet 在所有營運司法管轄區內，**絕對不被認定為博弈、彩券或衍生性金融商品服務**，並建立可被監管稽核的法律證據鏈。

### 1.1 合規黃金三原則（Non-negotiable）

| 原則 | 內涵 | 違反代價 |
|------|------|----------|
| ① 點數不可回兌（No Cash-out） | 站內點數絕對不可換回現金、加密貨幣、商品、第三方禮品卡、其他平台儲值 | 觸法即關站、創辦人刑責 |
| ② 平台不下場（No House Position） | 平台不持倉、不對賭、不從玩家輸贏中獲利，僅收手續費 | 違反即等同莊家 |
| ③ 全程稽核留痕（Full Audit Trail） | 所有金流、撮合、結算、判定皆有不可竄改之事件流，保存 7 年以上 | 監管稽核失敗即吊照 |

### 1.2 反向定義（這些行為會立即把專案打回博弈紅線）

- ❌ 玩家點數可轉讓給另一名玩家（即使是「贈送」）
- ❌ 玩家點數可在二級市場交易（即使是場外）
- ❌ 平台舉辦「點數兌獎」活動，獎品為實體商品 / 商品禮券 / 加密貨幣
- ❌ 平台開放任何形式的「會員提現」（即使是手續費代扣形式）
- ❌ 平台對玩家輸贏抽成（必須是「對交易行為抽成」而非「對輸贏抽成」）
- ❌ 平台代為持有第三方資金並進行投資操作

## 2. 經營主體架構（Corporate Structure）

### 2.1 法律實體拓撲

                    │  PropheticaNet Holdings (BVI)   │  ← 控股公司（稅務最佳化）
                    └────────────┬────────────────────┘
                                 │ 100% 持股
                  ┌──────────────┴──────────────┐
                  ▼                              ▼
        ┌──────────────────────┐    ┌──────────────────────────┐

| 雇用台灣員工 | ❌ | ❌ | ✅ |

### 2.3 為何台灣子公司不接觸玩家資金

> 中華民國刑法 §268「圖利供給賭場罪」適用於**在中華民國境內**提供賭博場所或聚眾賭博者。

只要：
1. 玩家**簽約對象**為境外 Operating Co.（ToS 明確標示）
2. 玩家**入金收受方**為境外金流通路（不經台灣銀行帳戶）
3. 台灣公司**僅提供軟體開發、客服外包**等中性技術服務

則台灣子公司在法律上等同於「外包軟體公司」，類似目前許多境外電商平台在台設立的研發中心。

> 注意：本 SPEC 為內部技術合規指南，**正式法律意見書必須由台灣 / 境外執照地律師雙重出具**，不得僅以本 SPEC 作為法律依據。

## 3. Geo-block 矩陣

### 3.1 司法管轄區分級

| 等級 | 司法區 | 處理 | 理由 |
|------|--------|------|------|
| 🔴 完全封鎖 | 美國全境（含 USVI / 波多黎各）| 從註冊、登入、API 全層封鎖 | CFTC 對 prediction market 採嚴格牌照制（DCM）|
| 🔴 完全封鎖 | 中國大陸 | 同上 | 賭博全面違法 |
| 🔴 完全封鎖 | 加拿大 Ontario 省 | 同上 | iGaming Ontario 牌照制 |
| 🔴 完全封鎖 | 法國 | 同上 | ARJEL 牌照制 |
| 🟠 強化驗證 | 新加坡 | 入金限額 + 強制 KYC | 賭博法嚴格 |
| 🟠 強化驗證 | 香港 | 同上 | 博彩稅條例 |
| 🟡 標準審查 | 台灣 | 標準 KYC + 不可出金限制 | 主市場，需嚴守 §268 |
| 🟢 一般市場 | 日 / 韓 / 越 / 馬 / 菲（需個案）| 標準 KYC | 視 Operating Co. 牌照覆蓋 |

### 3.2 技術實作層級

Geo-block 必須**多層防禦**，單一層被繞過不導致違規：

```
Layer 1: Cloudflare WAF Geo-rule
  └─→ 拒絕來自 🔴 國家 IP 的所有請求（含 API、靜態資源）
Layer 2: 應用層 IP Geolocation 驗證
  └─→ MaxMind GeoIP2 + IP2Location 雙來源比對，差異則拒絕
Layer 3: 註冊時 KYC 國籍 / 居住地驗證
  └─→ 證件國籍為 🔴 名單則拒絕開戶
Layer 4: 行為偵測
  └─→ 連續 VPN 切換、時區與 IP 不符、IP 地理快速跳動 = 強制重新 KYC
Layer 5: 支付 Gateway BIN 檢查
  └─→ 信用卡 BIN 屬 🔴 名單則拒收
```

### 3.3 VPN 政策（重新定位）

| 場景 | 處理 |
|------|------|
| 用戶從 🔴 名單 IP + VPN 登入（實際國籍為🔴）| 拒絕。違反 ToS。 |
| 用戶從一般市場 IP + 隨後切 VPN | 觸發 Layer 4，要求重新 KYC |
| 用戶**已通過 KYC 確認非🔴名單居民** + 偶爾使用 VPN（出差） | 允許，但記錄日誌 |
| 「VIP / 商品購買達標」內容區 | **獨立功能**，使用站內 Token Gating，**與 IP / VPN 無關** |

> ⚠️ 原 PRD 中「VPN 強制開啟（法規規避）」的描述**完全刪除**。VPN 不能作為合規手段。VIP 內容區改用「會員等級 / 持有特定虛擬商品」作為閘門。

## 4. 玩家服務條款（ToS）關鍵條款

實作時 ToS 必須由執照地律師起草，但**以下要點為技術條件，必須在 UI / API 強制執行**：

### 4.1 必含條款

| 條款 ID | 內容摘要 | 對應技術機制 |
|---------|----------|--------------|
| ToS-001 | 玩家點數為**遊戲內虛擬道具**，無現金價值 | 後端絕無「點數→現金」API |
| ToS-002 | 玩家點數**不可贈送、轉讓、二級市場交易** | wallet 服務無 transfer-to-user API |
| ToS-003 | 玩家年齡須 ≥ 18 歲，KYC 不通過則停權 | 註冊時生日驗證 + KYC 強制 |
| ToS-004 | 平台保留判定權，但設立**24 小時申訴窗口** | 結算狀態機含 `disputed` 狀態 |
| ToS-005 | 玩家須同意責任博弈條款，**設定每月儲值上限** | 強制 first-time deposit 流程 |
| ToS-006 | 平台收取交易手續費，**不分享玩家輸贏** | 帳本以 trade volume 為計費基礎 |
| ToS-007 | 任何**洗售、操縱、多帳號**行為導致永久停權 | 反作弊偵測 + 自動觸發 KYC |
| ToS-008 | 平台對技術故障、停盤、結算錯誤之**最大責任**為玩家當次儲值金額 | 條款級限制，後端事件記錄 |

### 4.2 點擊同意設計

- 註冊：勾選「我已閱讀並同意 ToS、隱私政策、責任博弈聲明」三個獨立 checkbox（不得單一全選）
- ToS 修改：以站內訊息 + Email 雙重通知，玩家須在 30 日內重新確認，否則帳戶凍結
- 所有同意紀錄存入 `tos_consent_logs` 表，含時間戳、IP、User Agent、ToS 版本 hash

## 5. 監管稽核資料保留

### 5.1 必留資料清單與保留期限

| 資料類型 | 保留期限 | 不可竄改性要求 |
|----------|---------|---------------|
| KYC 證件影像 | 7 年（最後一次活動後）| 加密 + 存取記錄 |
| 玩家所有金流事件 | 7 年 | WORM (Write-Once-Read-Many) Object Lock |
| 撮合事件流（每筆 trade）| 5 年 | append-only log，hash chain |
| 結算判定紀錄 | 5 年 | 數位簽章 + 多人簽核日誌 |
| 客服對話紀錄 | 3 年 | 加密儲存 |
| 系統操作日誌（admin 行為）| 5 年 | 不可竄改稽核日誌 |
| 反洗錢可疑交易報告（STR）| 5 年（提交後）| 加密 + 限定存取 |

### 5.2 資料儲存位置策略

| 資料類別 | 儲存位置 | 跨境合規處理 |
|---------|---------|--------------|
| KYC 證件 | Cloudflare R2（EU region）+ Object Lock | 與玩家簽署跨境傳輸條款 |
| 撮合事件流 | Linode Object Storage (Tokyo) + AWS S3 (Singapore) 雙寫 | 主市場本地儲存 |
| 系統日誌 | Loki + Grafana Cloud | TLS + at-rest 加密 |
| 玩家行為分析 | ClickHouse 自建 | 匿名化處理 |

## 6. 責任博弈強制最低要求（呼應 SPEC-006）

雖然詳規見 SPEC-006，但以下為法律強制最低門檻：

- 註冊時必須詢問每月儲值上限（不可預設無上限）
- 提供「自我排除」永久封號功能
- 顯示「玩家累計儲值」於每次儲值頁面
- 連續登入超過 3 小時主動跳出冷靜提示
- 未成年保護：證件年齡 < 18 直接拒絕，KYC 證件造假入刑事責任條款

## 7. 個資保護與隱私政策框架

### 7.1 適用法規

| 法規 | 觸發條件 | 主要要求 |
|------|---------|---------|
| 台灣個資法 | 處理台灣居民個資 | 告知義務、安全維護、跨境傳輸聲明 |
| 歐盟 GDPR | 任何 EU 居民個資 | 資料主體權、72hr 通報、DPO |
| 加州 CCPA / CPRA | 加州居民個資 | Do Not Sell My Personal Info |
| PDPA 新加坡 | 新加坡玩家 | 同意制 |

### 7.2 玩家權利實作對應

| 權利 | 技術實作 |
|------|---------|
| 查詢權 | `GET /api/v1/me/data-export`（24h 內生成 zip） |
| 更正權 | `PATCH /api/v1/me/profile`（敏感欄位需重新 KYC） |
| 刪除權 | `DELETE /api/v1/me/account`（軟刪除，KYC 紀錄保留 7 年至法律要求） |
| 攜帶權 | data-export 包含 JSON 格式可攜資料 |
| 反對權 | 行銷推播 opt-out cookies / preferences |

### 7.3 Cookie 政策實作

- 三類 Cookie：必要 / 功能 / 行銷
- 必要 Cookie 不需同意（含 session、CSRF token）
- 功能與行銷 Cookie **預設不啟用**，需玩家明確同意
- 同意紀錄存於 first-party cookie + 後端 audit log

## 8. 反洗錢（AML）框架（呼應 SPEC-005）

### 8.1 法律最低基準

| 規範 | 觸發條件 | 對應措施 |
|------|---------|---------|
| FATF Recommendations | 任何金流業務 | KYC、可疑交易申報、客戶風險評級 |
| 台灣洗錢防制法 | 台灣公司涉及金流 | 由境外 Operating Co. 主責，避免觸發 |
| 執照地 AML 法規 | 視 Malta / Curaçao 而異 | 執照條件決定 |

### 8.2 強制觸發 EDD（Enhanced Due Diligence）的情境

- 單筆儲值 > USD 10,000 等值
- 30 日累計儲值 > USD 30,000 等值
- 玩家來自高風險國家（FATF Grey/Black List）
- 玩家為政治公眾人物（PEP）或其親屬
- 異常行為（短時間內大額儲值 + 未交易）

## 9. 風險與失敗情境

| 風險 | 機率 | 影響 | 緩解 |
|------|------|------|------|
| 台灣司法機關認定 §268 賭博罪 | 中 | 創辦人刑責 + 服務中斷 | 嚴守無出金原則 + 主體在境外 + 法律意見書 |
| 執照地監管收緊 | 低 | 重新申請執照 | 雙執照備案（Malta + Curaçao）|
| 個資外洩 | 中 | GDPR/個資法重罰 | 加密、Vault、最小權限 |
| 玩家集體訴訟（爭議結算）| 中 | 賠付 + 名譽 | ToS-008 限額 + 申訴窗口 + 仲裁條款 |
| 第三方支付通路撤資 | 高 | 入金通路中斷 | 至少 3 家備援、定期 audit |

## 10. 驗收條件（Acceptance Criteria）

- [ ] 三家公司架構在 BVI / 執照地 / 台灣完成註冊，提供註冊證書
- [ ] Operating Co. 取得至少一張正式遊戲執照
- [ ] ToS / Privacy Policy / Responsible Gaming Statement 三份文件由執照地律師審閱蓋章
- [ ] Geo-block Layer 1-5 全數實作，並通過跨地區渗透測試（含 VPN 模擬）
- [ ] 資料保留與不可竄改性配置完成（R2 Object Lock 啟用）
- [ ] 玩家權利 5 項 API 可被外部調用測試
- [ ] 反洗錢 EDD 觸發規則自動化執行驗證
