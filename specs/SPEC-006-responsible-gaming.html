SPEC-006 — 責任博弈機制（Responsible Gaming）

優先級：P1 版本：v0.1.0 · 最後更新：2026-05-05 依賴：無 被依賴：SPEC-012

1. Objective

建立業界標準的責任博弈（Responsible Gaming, RG）機制，避免玩家陷入過度沉迷，並滿足執照地監管要求。即便平台定位為「娛樂遊戲」，沉迷風險仍存在，且完整 RG 設計是執照核發的必要條件。

2. 核心機制清單

機制 性質 觸發方式
儲值上限（Deposit Limit） 強制 註冊時必設 + 玩家可調整
下注上限（Wager Limit） 可選 玩家自願設定
損失上限（Loss Limit） 可選 玩家自願設定
登入時長提醒（Session Time Reminder） 強制 連續登入 1 / 2 / 3 小時自動跳出
冷靜期（Cool-off Period） 強制可選 24h / 7d / 30d 暫停所有交易
自我排除（Self-Exclusion） 強制可選 6 個月 / 1 年 / 永久封號
未成年保護 強制 註冊時年齡驗證 + KYC 強制
沉迷指標監測 強制 系統自動標記，主動關懷
第三方協助資源 強制 站內顯示 RG 援助電話 / 網站

3. 註冊強制流程

3.1 必經頁面（不可跳過）

  1. 年齡確認（生日輸入）
    • < 18 歲 → 拒絕註冊
    • 顯示「本平台為成年娛樂遊戲，未成年禁止使用」
  2. 責任博弈聲明
    • 完整文字（白話版）+ 玩家勾選同意
    • 必含「無回兌、僅虛擬點數、勿過度投入」聲明
  3. 儲值上限設定
    • 月儲值上限：必須在 TWD 1,000 / 5,000 / 30,000 / 100,000 / 自訂中擇一
    • 預設不可選擇「無上限」
  4. 援助資源連結
    • 顯示台灣戒癮諮詢專線、相關支援團體連結

3.2 上限調整規則

  • 降低上限：立即生效
  • 提高上限：
    • 24 小時冷卻期（防止衝動）
    • 過去 30 日無觸碰當前上限 → 才允許申請
    • 過去 30 日有 RG 風險訊號 → 拒絕

4. 沉迷指標與主動關懷

4.1 RG 風險評分（每日計算）

declared_monthly_income 之欄位定義與 fallback 規則見 SPEC-005 §2.1.1。當玩家未申報（NULL）時，「儲值 / 月收入比」維度視為中性（不加分）。

工程實作細節已抽離至 SPEC-006-responsible-gaming-implementation-plan.html（涵蓋 schema、API、流程、部署與驗收）。

4.2 評分對應行動

分數 處置
0–30 無
31–50 站內訊息推播 RG 提醒
51–70 強制中斷 + 顯示援助資源頁 + 30 分鐘冷卻
71–85 Compliance 客服主動聯繫確認狀態
86–100 強制冷靜期 24 小時 + 須客服解鎖

4.3 監控頻率

  • 即時觸發（單一行為）：連續登入時長、大額下注
  • 每日 batch（每日凌晨 02:00 UTC）：累計指標
  • 每週 review：高分玩家由 Compliance 人工檢視

5. 自我排除（Self-Exclusion）

5.1 三種模式

模式 期限 解除條件
Cool-off 24h / 7d / 30d 自動到期解除
Time-out 6 個月 / 1 年 到期後玩家主動申請 + 14 天延長冷靜期
Permanent 永久 不可解除（註冊新帳戶必被識別並拒絕）

5.2 排除期間

  • 帳戶完全凍結（無法登入、無法儲值、無法交易、無法收任何通知）
  • 既有持倉正常結算（不沒收）
  • 結算後點數轉至「凍結錢包」
  • 永久排除：點數依玩家選擇 → ① 留作 6 個月後若解除可恢復 ② 捐贈合作戒癮機構（玩家簽字）

5.3 跨平台排除（GAMSTOP-style）

執照地若有跨平台排除制度（如英國 GAMSTOP），平台需整合：

  • 玩家自我排除自動同步至跨平台名單
  • 註冊時檢查跨平台名單，命中則拒絕

台灣無類似制度，但需在執照地（Malta / Curaçao）合作的 RG 第三方平台註冊。

5.4 防再註冊

  • KYC 證件號碼 hash 命中 self-excluded 名單 → 拒絕新註冊
  • 同 device fingerprint + 同 IP + 修改個資 → 標記為可疑、要求人工 review

6. 未成年保護

6.1 強制機制

  • 註冊年齡 < 18 → 拒絕
  • KYC 證件年齡 < 18 → 立即停權 + 退款已儲值（依 SPEC-002 退款流程）
  • 偵測到未成年使用成年人帳戶（透過行為 / 客服）→ 立即停權

6.2 行銷規範

  • 平台對外行銷素材不得含未成年形象 / 動漫吸引未成年元素
  • 廣告版位禁止投放於未成年集中平台
  • 推送通知 / Email 不得鎖定 18 以下用戶名單

7. UI / UX 必含元素

7.1 頁尾固定資訊

工程實作細節已抽離至 SPEC-006-responsible-gaming-implementation-plan.html（涵蓋 schema、API、流程、部署與驗收）。

7.2 儲值頁面

  • 顯示「本月已儲值 / 月上限」進度條
  • 接近上限（80%）醒目警告
  • 達上限 100% 直接拒絕儲值動作

7.3 個人帳戶頁

獨立區塊「責任博弈」，含：

  • 月度活動報告（儲值、下注、結算）
  • 上限設定 / 調整
  • 自我排除入口
  • 援助資源連結

7.4 連續登入提醒

  • 連續登入滿 1 小時：modal 提示「已遊戲 1 小時，建議休息」（可繼續）
  • 連續滿 2 小時：強制顯示 + 5 分鐘暫停期
  • 連續滿 3 小時：強制中斷 + 30 分鐘冷卻 + 跳出 RG 評估問卷

8. 客服 RG 介入流程（呼應 SPEC-012）

觸發 客服動作
RG 評分 71–85 主動 Email + 站內訊息（標準範本）
RG 評分 86+ 電話聯繫 + 強制冷靜期
玩家主動求助 個人化 RG 計畫（限額調整、時段限制）
親友通報 接受第三方通報，啟動人工審核（不可直接以親友通報為由停權，須玩家自行確認）

客服必須完成 RG 培訓認證才可處理此類個案。

9. 監管報表

報表 頻率 內容
Monthly RG Report 每月 自我排除人數、平均沉迷分數、強制中斷次數
Quarterly RG Audit 每季 沉迷個案處理紀錄抽樣
Annual RG Effectiveness Review 每年 對比指標、改善計畫

10. 驗收條件

  • 註冊強制 RG 流程不可跳過
  • 上限調整規則自動化執行
  • RG 評分批次每日 02:00 完成 < 30 分鐘
  • 高分玩家自動觸發客服工單
  • 自我排除帳戶完全凍結，KYC hash 名單比對成功
  • 連續登入提醒 modal 邏輯通過 E2E 測試
  • 監管報表自動產生

11. Open Questions

  1. RG 評分模型是否使用第三方（如 Mindway AI）還是自建？
  2. 跨平台排除整合：執照地是否強制？哪個 service？
  3. 玩家公益捐贈點數的稅務處理（玩家在排除時將點數捐出）？
  4. 連續登入時數計算：跨會話如何累計？（24h 內第二次登入是否重新計算）
  5. 是否提供「家人代申請」管道？（多數法律不允許，需確認）
