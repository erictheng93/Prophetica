4. INV-6 white-list trigger 擴展（規格 §4.3 / ADR-0007）

以下為對 migrations/202605070004_inv6_outflow_whitelist.sql 之 後續 migration 規劃內容。ADR-0007 Accepted 後另開檔（建議檔名 202607NNNN_inv6_redemption_carveout.sql，NNNN 為當批次序），不要就地修改既有 trigger 檔。 

-- 新 migration：INV-6 white-list 追加 (g) Liability.UnredeemedEntitlement carve-out（ADR-0007 §4.1 (g)）
-- 配合 INV-7 user_id 同人綁定（新 trigger，§5 本 plan）

CREATE OR REPLACE FUNCTION fn_inv6_outflow_whitelist_check()
RETURNS TRIGGER AS $$
DECLARE
    v_account_code TEXT;
    v_violation_account TEXT;
BEGIN
    SELECT code INTO v_account_code
    FROM ledger_accounts WHERE id = NEW.account_id;

    IF v_account_code IS NULL
       OR v_account_code NOT LIKE 'Player.Wallet.%'
       OR NEW.direction <> 1 THEN
        RETURN NULL;
    END IF;

    SELECT a2.code INTO v_violation_account
    FROM ledger_entries e2
    JOIN ledger_accounts a2 ON e2.account_id = a2.id
    WHERE e2.txn_id = NEW.txn_id
      AND e2.direction = -1
      AND NOT (
          a2.code LIKE 'Player.Locked.%'
          OR a2.code LIKE 'Player.Frozen.%'
          OR a2.code = 'Revenue.TradingFee'
          OR a2.code = 'Revenue.SettlementFee'
          OR (a2.code LIKE 'Player.Wallet.%'
              AND EXISTS (
                  SELECT 1 FROM ledger_transactions t
                  WHERE t.id = NEW.txn_id
                    AND t.txn_type IN ('trade', 'settle')
              ))
          OR (a2.code LIKE 'Bank.TrustAccount.%'
              AND EXISTS (
                  SELECT 1 FROM ledger_transactions t
                  WHERE t.id = NEW.txn_id
                    AND t.txn_type = 'chargeback'
              ))
          OR (a2.code = 'Expense.ManualPointsGrant'
              AND EXISTS (
                  SELECT 1 FROM ledger_transactions t
                  WHERE t.id = NEW.txn_id
                    AND t.txn_type = 'manual_points_adjustment'
                    AND t.metadata->>'adjustment_direction' = 'deduct'
                    AND t.metadata->>'actor_role' IN ('admin', 'manager')
                    AND COALESCE(t.metadata->>'audit_log_id', '') <> ''
              ))
          -- (g) Liability.UnredeemedEntitlement.{user_id} 限 redemption_purchase（ADR-0007 §4.1）
          OR (a2.code LIKE 'Liability.UnredeemedEntitlement.%'
              AND EXISTS (
                  SELECT 1 FROM ledger_transactions t
                  WHERE t.id = NEW.txn_id
                    AND t.txn_type = 'redemption_purchase'
                    AND COALESCE(t.metadata->>'order_id', '') <> ''
                    AND COALESCE(t.metadata->>'sku_id', '') <> ''
                    AND COALESCE(t.metadata->>'audit_log_id', '') <> ''
              ))
      )
    LIMIT 1;

    IF v_violation_account IS NOT NULL THEN
        RAISE EXCEPTION
            'INV-6 violation in txn %: Player.Wallet outflow targets non-whitelisted account "%"',
            NEW.txn_id, v_violation_account
        USING ERRCODE = '40004',
              HINT = 'See ADR-0007 §4.1 (g) for redemption carve-out; SPEC-024 §4.3.';
    END IF;

    RETURN NULL;
END;
$$ LANGUAGE plpgsql;

5. INV-7 trigger（user_id 同人綁定）— 新建

-- 新 trigger：INV-7（SPEC-024 §5）— redemption / fulfillment / refund / expiry 系列
-- txn 中，所有 Player.Wallet.{X} 與 Liability.UnredeemedEntitlement.{Y} entries 必須 X = Y。
--
-- 為何不靠 application：service 層 bug 或 admin 後台直連 PG 可能繞過；INV-7
-- 三層保護（CI grep + SDK validate + DB trigger）對齊 INV-6 之安全強度。

CREATE OR REPLACE FUNCTION fn_inv7_redemption_same_user_check()
RETURNS TRIGGER AS $$
DECLARE
    v_txn_type TEXT;
    v_user_ids TEXT[];
BEGIN
    SELECT txn_type INTO v_txn_type
    FROM ledger_transactions WHERE id = NEW.txn_id;

    IF v_txn_type NOT IN (
        'redemption_purchase',
        'entitlement_fulfillment',
        'redemption_refund',
        'entitlement_expiry'
    ) THEN
        RETURN NULL;
    END IF;

    -- 收集本 txn 中所有 Player.Wallet.{X} / Liability.UnredeemedEntitlement.{Y}
    -- entries 的 user_id 字尾，必須去重後只有 1 個（即同人）
    SELECT ARRAY_AGG(DISTINCT
        regexp_replace(a.code, '^(Player\.Wallet|Liability\.UnredeemedEntitlement)\.', '')
    )
    INTO v_user_ids
    FROM ledger_entries e
    JOIN ledger_accounts a ON e.account_id = a.id
    WHERE e.txn_id = NEW.txn_id
      AND (
          a.code LIKE 'Player.Wallet.%'
          OR a.code LIKE 'Liability.UnredeemedEntitlement.%'
      );

    IF v_user_ids IS NULL OR array_length(v_user_ids, 1) IS NULL THEN
        RETURN NULL;
    END IF;

    IF array_length(v_user_ids, 1) > 1 THEN
        RAISE EXCEPTION
            'INV-7 violation in txn %: redemption-family txn must not cross user_id boundary (got: %)',
            NEW.txn_id, v_user_ids
        USING ERRCODE = '40004',
              HINT = 'See SPEC-024 §5 INV-7; SPEC-002 §4.4.7 / Q-10 prohibits peer transfer.';
    END IF;

    RETURN NULL;
END;
$$ LANGUAGE plpgsql;

CREATE CONSTRAINT TRIGGER trg_inv7_redemption_same_user
AFTER INSERT ON ledger_entries
DEFERRABLE INITIALLY DEFERRED
FOR EACH ROW EXECUTE FUNCTION fn_inv7_redemption_same_user_check();
效能：INV-7 在每筆 ledger_entries insert 跑一次 regex；對 redemption 類 txn（typically 2 entries）overhead 可忽略。若 future workflow 把 redemption 與 trade 等高頻 txn 混在大 batch 內， 應切 statement-level trigger，呼應 ADR-0006 §5.2 Negative #2 的策略。

6. SDK 變更

在 crates/sdk/src/ledger/mod.rs 中：

  1. is_inv6_whitelisted_target() 增加 Liability.UnredeemedEntitlement.* 分支（限 txn_kind = RedemptionPurchase，需檢查 metadata 含 order_id / sku_id / audit_log_id）。
  2. 新增 LedgerTxnKind 變體： RedemptionPurchase、EntitlementFulfillment、RedemptionRefund、EntitlementExpiry。
  3. 新增 LedgerTransactionDraft::validate_redemption_same_user() — 在 application 層做 INV-7 早期攔截（呼應 ADR-0006 §4.2.2 之三層保護 pattern）。
  4. 新增 LedgerError::Inv7Violation variant。
  5. 測試：故意建構跨 user_id 之 redemption_purchase draft，驗 validate() 立即回傳 Inv7Violation；故意 bypass validate 直接寫入 DB（pg pool 整合測試）驗 trigger fail。

7. CI sentinel-scan 擴充

ADR-0006 §4.2.3 引述「CI sentinel-scan grep gate」；本 plan 順手把該 gate 之檔案路徑固定下來，並加入 SPEC-024 之新禁字： 

## .github/workflows/wallet-invariant-scan.yml（規劃路徑）
## 觸發：每個 PR；失敗時 block merge。
## 對應：ADR-0006 §4.2.3 / SPEC-024 §4.3 / SPEC-002 §4.4.7
name: wallet-invariant-scan
on: [pull_request]
jobs:
  red-line-grep:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: INV-6 / R-1 紅線檢查
        run: |
          rg -n \
            -e 'Player\.Wallet.*->\s*AccountsPayable' \
            -e 'Player\.Wallet.*->\s*OperatingAccount' \
            -e 'wallet_to_payable|cash_out_player_pts|redeem_points_to_cash' \
            --type rust services/ crates/ \
            && { echo '::error::INV-6 / R-1 violation: Player.Wallet outflow to external assets'; exit 1; } \
            || true
      - name: SPEC-024 / Q-10 紅線檢查（peer transfer）
        run: |
          rg -n \
            -e 'peer_transfer|wallet_to_wallet_gift|gift_points_to' \
            -e 'Player\.PendingTransfer\.' \
            -e 'Revenue\.PeerTransferFee' \
            --type rust services/ crates/ \
            && { echo '::error::Q-10 violation: peer point transfer is prohibited'; exit 1; } \
            || true
同步動作：SPEC-002 implementation plan §3.2 已補上對本 gate 之指標連結；ADR-0006 §4.2.3 之「待寫」CI grep gate 落地於此檔。

8. Service 骨架（規格 §3）

services/
└─ redemption-service/              ← library crate（domain logic）
   ├─ Cargo.toml
   ├─ src/
   │  ├─ lib.rs
   │  ├─ catalog/     (CatalogItem, SKU, Stock)
   │  ├─ order/       (Order state machine, idempotency)
   │  ├─ entitlement/ (state machine, lifecycle events)
   │  ├─ fulfillment/ (digital_immediate / digital_code / service_async)
   │  └─ refund/      (cancel window, CS-driven refund)
   └─ migrations/                   ← redemption 專屬 schema
services/_binaries/
└─ redemption-api/                  ← binary（thin axum + tonic）
   ├─ Cargo.toml
   └─ src/main.rs

所有 ledger 寫入不直接呼叫 wallet-ledger-service 之 PG client，而是透過 crates/sdk/src/ledger 之 LedgerClient， 確保 INV-6 / INV-7 application-level validate 都先過一次。

9. 測試矩陣

測試類別 內容 必過門檻
Migration / Trigger 新增 ledger_accounts；INV-6 trigger 通過 redemption_purchase 合法路徑；故意把 dest 換成 Liability.AccountsPayable.* 必 fail 100% 路徑覆蓋
INV-7 同人綁定 redemption_purchase 跨 user_id 必 fail；fulfillment / refund / expiry 跨 user_id 必 fail；同 user 之合法路徑通過 SDK 與 PG 雙層測試皆通過
Order 狀態機 所有合法 / 非法 transition；idempotency 重送回原結果 狀態圖每 transition 至少 1 test

過期 sweep 邊界（剛過期 vs 未過期）；breakage 帳目正確 property test
