SPEC-015 market lifecycle implementation plan

版本: v0.1.1
更新日: 2026-05-09
對應規格: SPEC-015
目標: 落實市場生命週期 state machine、表結構與權限分流

1. 資料模型（實作）

CREATE TABLE markets (
  id VARCHAR(64) PRIMARY KEY,
  market_type VARCHAR(32) NOT NULL,
  symbol VARCHAR(64) NOT NULL,
  status VARCHAR(16) NOT NULL, -- DRAFT / REVIEW / SCHEDULED / OPEN / CLOSED
  created_by BIGINT NOT NULL,
  reviewed_by BIGINT,
  opens_at TIMESTAMPTZ,
  closes_at TIMESTAMPTZ,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE TABLE market_reviews (
  id BIGSERIAL PRIMARY KEY,
  market_id VARCHAR(64) NOT NULL REFERENCES markets(id) ON DELETE CASCADE,
  reviewer_role VARCHAR(32) NOT NULL,
  decision VARCHAR(32) NOT NULL, -- approve/reject/require_changes
  decided_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  remarks TEXT
);

CREATE TABLE market_audit_logs (
  id BIGSERIAL PRIMARY KEY,
  market_id VARCHAR(64) NOT NULL REFERENCES markets(id) ON DELETE CASCADE,
  actor_user_id BIGINT NOT NULL,
  action VARCHAR(32) NOT NULL,
  old_status VARCHAR(16),
  new_status VARCHAR(16),
  payload_json JSONB NOT NULL DEFAULT '{}',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

2. 流程（狀態機）

DRAFT → REVIEW → SCHEDULED → OPEN → CLOSED
  • CLOSED 交由 SPEC-004 申訴/結算處理，不再進入本機制。
  • 狀態變更需要 `market_reviews` 審核軌跡（雙人簽核、legal/compliance 視情境）。

3. 權限與操作

  • CREATE in DRAFT：市場建立者 + 具備風控預備權限。
  • REQUEST REVIEW：可由編輯角色送審，記錄 submit trace。
  • SCHEDULE / OPEN：需雙人審核結果，`REVIEW` 才可進 SCHEDULED。
  • force CLOSE：僅 Admin 可發起，需強制原因。

4. 不變式

  • 同一市場任意時間至多一筆 OPEN 或 OPEN 之前排程。
  • 一旦進入 REVIEW，不得繞過 `market_reviews` 寫入 `market_audit_logs`。
  • Oracle 提交資料結構固定，避免跨欄位寫入不一致。

5. 驗收與監控

  • 審核節點與角色寫入可查詢。
  • 關閉後不得改變交易狀態欄位。
  • 監控項目：未按時 review、非法狀態跳轉、關閉後重啟嘗試。
