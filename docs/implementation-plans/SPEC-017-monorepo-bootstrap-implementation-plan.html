SPEC-017 monorepo bootstrap implementation plan

版本: v0.2.6
更新日: 2026-05-09
對應規格: SPEC-017
目標: 建立可重現開發環境與 PR #1 動工前 PoC gating

1. 開發前置（Environment）

git clone
rtk make dev
rtk pnpm install --frozen-lockfile
make doctor
make ci-setup
  • Node/Rust/python 工具鏈版本由 `make doctor` 驗證。
  • `.sqlx` 與 proto/stubs 維持可重建性。

2. 目錄與模組邏輯

services/api-gateway/
services/matching-engine/
services/ledger-service/
packages/sdk/
packages/proto/
tools/
  • Rust crate 與 Node 套件分別維持 ownership 區隔，但共用 workspace 版本策略。
  • docs/poc 與 ADR 跨規格引用，避免重複決策文檔。

3. CI Bootstrap

  • PR pipeline：lint + test + sentinel-scan 為最小通過條件。
  • main pipeline：加入 sqlx/check、nextest、clippy、prettier/eslint、fmt 驗證。
  • PR #1 前置 gating：PoC-A（EdDSA/LIFF）+ PoC-B（Edge runtime）必須有通過紀錄。

4. 工具鏈硬性

  • Rust 1.85+、rust-toolchain lock、sqlx cli、buf、cargo-deny。
  • Node：.nvmrc 與 packageManager（pnpm）需一致。
  • GitHub Actions runner 與 cache key 不得自行硬改。

5. 不變式

  • make dev 必須一次啟動至少一組前後端可用服務。
  • PoC 未回填不得 merge PR #1。
  • 任何 bootstrap 失敗訊息需可重現並可在 1 小時內復現。

6. 交付清單

  1. 完成 bootstrap docs 與新進工程師 15 分鐘可跑起流程。
  2. CI pipeline 可跑完 bootstrap gates。
  3. PoC gating 指標入庫並提供最小可證明文件。
