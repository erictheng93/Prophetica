SPEC-018 Auditability & Evidence Pack implementation plan

版本: v0.1.0
更新日: 2026-05-09
對應規格: SPEC-018
目標: 把可追溯、可稽核、可匯出變成可落地的工程任務

1. 目的與邊界

  • 此文件為稽核與證據化的工程化實作計畫，不替代產品規格。
  • 聚焦：不可變更歷史（immutable log）、4-eye 變更錄、事件關聯、證據封包（Evidence Pack）導出。
  • 不聚焦：新風控模型設計與機器學習規則（保留在 SPEC-010）。

2. 核心資料儲存

2.1 audit_events

CREATE TABLE audit_events (
  id BIGSERIAL PRIMARY KEY,
  event_id UUID NOT NULL UNIQUE DEFAULT gen_random_uuid(),
  aggregate_type TEXT NOT NULL,
  aggregate_id BIGINT NOT NULL,
  action TEXT NOT NULL,
  actor_id BIGINT NOT NULL,
  actor_role TEXT NOT NULL,
  actor_ip INET NOT NULL,
  occurred_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  correlation_id UUID NOT NULL,
  request_id TEXT NOT NULL,
  payload_hash CHAR(64) NOT NULL,
  payload JSONB NOT NULL DEFAULT '{}',
  idempotency_key TEXT,
  source_service TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  created_by BIGINT NOT NULL,
  status TEXT NOT NULL
);

2.2 audit_event_attachments

CREATE TABLE audit_event_attachments (
  id BIGSERIAL PRIMARY KEY,
  audit_event_id BIGINT NOT NULL REFERENCES audit_events(id),
  evidence_type TEXT NOT NULL,
  object_uri TEXT NOT NULL,
  object_hash CHAR(64) NOT NULL,
  object_size BIGINT NOT NULL,
  redacted BOOLEAN NOT NULL DEFAULT FALSE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

2.3 invariant_checks

CREATE TABLE invariant_checks (
  id BIGSERIAL PRIMARY KEY,
  check_name TEXT NOT NULL,
  scope TEXT NOT NULL,
  check_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  result TEXT NOT NULL,
  details JSONB NOT NULL DEFAULT '{}',
  actor_id BIGINT NOT NULL,
  evidence_pack_id BIGINT
);

2.4 report_exports

CREATE TABLE report_exports (
  id BIGSERIAL PRIMARY KEY,
  report_type TEXT NOT NULL,
  requested_by BIGINT NOT NULL,
  requested_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  from_ts TIMESTAMPTZ NOT NULL,
  to_ts TIMESTAMPTZ NOT NULL,
  status TEXT NOT NULL,
  storage_uri TEXT NOT NULL,
  manifest_uri TEXT NOT NULL,
  retention_until TIMESTAMPTZ NOT NULL,
  retention_policy TEXT NOT NULL
);

3. 約束條件（Invariants）

  • audit_events 僅新增不刪除（APPEND ONLY），只允許在合法保留窗口內做 soft-archive 標記。
  • payload_hash 以 event payload canonical JSON 計算，匯出時需驗證 hash 與重算值一致。
  • 對外回應/管理介面中的 idempotency_key 全域唯一。
  • 任何影響資金、帳戶層級決策、風控封鎖、人工審核的操作，必須同時寫入 audit_events。
  • evidence_type 需能映射到 report_export 的來源；report_export 必須包含 manifest。
  • audit_events 與 report_exports 皆需可依 correlation_id 反查到完整事件鏈。

4. 實作流程

4.1 事件接收

  • 以 outbox 或 middleware 包裝所有管理員 action、風控 action、支付/帳務關鍵 action。
  • 對事件打上 correlation_id、request_id、actor identity。
  • 寫入 audit_events 之前先校驗必填欄位與 hash。

4.2 附件封裝

  • 原始日志、工單、裁決摘要、交易批次檔均可封包進 attachment。
  • 附件上傳到 object storage 前先做壓縮與 hash。
  • 附件與事件保留一致生命週期，不得過早刪除。

4.3 Evidence Pack 產出

  • 輸入條件：report_type、時間窗、範圍、scope。
  • 輸出條件：manifest（json）+ zip 包。
  • manifest 含欄位： 1. report_id 2. generated_at 3. coverage 4. count_events 5. invariant_checks
  • 輸出後立即產生 audit_event 記錄，記錄匯出人、條件與結果。

5. 交付與整合

  • 後台新增「稽核匯出」功能，支援 CSV / ZIP / JSON manifest。
  • 為 KYC、交易、佣金、支付與客服事件提供預設模板。
  • 新增自訂保留政策：7 年法務資料、3 年一般營運資料。
  • 提供「重建報表」與「覆核紀錄差異報告」。

6. 權限與遮罩

  • 稽核匯出與附件下載僅限審計角色 + 指定 compliance 角色。
  • 對 PII 欄位做 field-level mask，若需要明文，須通過強化許可。
  • 所有敏感欄位訪問都寫入 audit_events。

7. 監控與異常

  • 每日比對事件筆數與實體匯入筆數，一致性不符立即觸發警報。
  • export_queue 失敗、hash mismatch、manifest 不可驗證必須進入 incident 路徑。
  • 舊版 report_type 僅做 read-only，禁止新增欄位破壞回放。

8. 驗收（工程）

  1. 資料表與索引建立完成，資料庫遷移可回滾。
  2. 管理員 action 100% 可對應至少一筆 audit_events。
  3. 每次 Evidence Pack 匯出都生成 manifest，並可透過 hash 驗證。
  4. 回填測試：刪除並重建某時間窗，版本差異可追溯且可比對。
  5. PII 可見行為符合遮罩政策並有審計記錄。
  6. 3 個保留期測試通過（7 年、3 年、1 年）。
