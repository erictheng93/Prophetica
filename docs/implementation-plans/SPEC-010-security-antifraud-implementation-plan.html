SPEC-010 — 安全與反作弊實作計畫

規格參照：SPEC-010-security-antifraud.html · 版本：v0.1.0

1. 實作邊界

  • 基礎設施防護（WAF、Rate limiting、DDoS、bot）
  • 應用層認證授權（JWT、refresh、step-up、revocation）
  • 反作弊模型與帳號接管 / chargeback 保護
  • 治理簽核集中到 multi-sig 中央表。

2. 安全不變式

  • INV-SEC-1：Session 以短效 access + 可更新 refresh，refresh 一次性使用。
  • INV-SEC-2：refresh reuse 檢測會撤銷所有 sessions 並觸發通知。
  • INV-SEC-3：高敏感 API 必檢查 step-up 有效欄位。
  • INV-SEC-4：多帳號風險 > 閥值必入 Compliance review queue。
  • INV-SEC-5：anti-cheat 所有高風險操作保有可觀測與審計紀錄。
  • INV-SEC-6：multi-sig 規則僅來源於中央表（MS-1 ~ MS-17）。

3. 身份驗證資料表

  • 新增/維護：user_sessions（refresh hash, used_at, successor_id, revoked_at）。
  • user/driver token claim 對齊：iss、aud、sub、jti、proph_* claims。
  • Refresh token reuse 事件寫入 SIEM / incident channel。

4. Token 與邊界流程

4.1 JWT

  • 主流程採 EdDSA，若 PoC 回報 LIFF 無法支援則開 split-algo 路線。
  • cookie mode：HTTP-only / secure / same-site=lax。

4.2 Refresh

  • 每次 /api/auth/refresh 發新 token 並將舊 token 標記 used。
  • reuse 時全部撤銷，要求全域重新登入。

5. 業務風控實作

威脅偵測項目處置
自我成交交易雙方連結圖譜、循環交易標記並進 STP / suspension
洗售新帳戶異常量能 + 異常成交限速與手動 review
Pump & Dump事件前結算前 30 分鐘不正常集中買單自動 freeze / 人工審核
Chargeback黑名單 BIN 與多次失敗帳本反沖 + 封號

6. 觀測與告警

  • 新增 security 指標：login anomaly、device collision、self-trade、wash score、chargeback.
  • 6 個月一次紅隊、bug bounty、季度社工測試。
  • 高風險事件 72h 內通報流程（若涉及個資）。

7. Multi-sig 中央表實作

  • 以 ms_id 驅動前端/後端權限；所有規則（MS-1 ~ MS-17）採表驅動。
  • 後端 schema 包含 ms_rule_code、signers、decision、approval_snapshot。
  • 審核 API 應回傳 ERROR_CODE_MULTISIG_REJECTED 及拒絕原因。
  • audit_logs 必含 ms_id、subject、metadata。

8. 驗收

  • WAF / RBAC / injection countermeasures 完成並有 CI gate。
  • refresh 重放防護與 step-up 可用性測試。
  • 安全敏感模組遵循 4-eye 或規定簽核。
  • 多簽表與 spec 依賴（008/015/012/013/017）一致。
