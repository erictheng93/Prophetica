SPEC-006 — Responsible Gaming 實作計畫

規格參照：SPEC-006-responsible-gaming.html · 版本：v0.1.0

1. 實作目標

  • 上線必經 RG 入口（年齡、聲明、儲值上限設定）。
  • 實作日批次 RG 分數與風險事件。
  • 實作自我排除名單查詢與凍結流程。
  • 提供客服與監管可查詢報表。

2. 不變式

  • INV-RG-1：任何未通過年齡驗證的帳號不得保留有效會話。
  • INV-RG-2：儲值上限不可為「無上限」預設。
  • INV-RG-3：減少上限立即生效，增加上限需通過 cooldown + 條件檢查。
  • INV-RG-4：冷靜期/自我排除帳號不得下單、不得儲值，例外僅持倉正常結算。
  • INV-RG-5：KYC hash 一致且命中自我排除者禁止新註冊。

3. 資料結構

  • rg_profiles：deposit_limit、wager_limit、loss_limit、session reminder state、lifecycle。
  • rg_scores：每日 30d/7d 的分項欄位與版本。
  • self_exclusion_records：模式、期間、reason、解除條件、觸發人員。
  • rg_interventions：客服介入紀錄、提醒方式、結果。

4. 計分與門檻（工程實作）

依規格公式實作欄位計分：

  • 存取行為：7d / 24h 上下傳入次數。
  • 存款相對於收入：30d deposit / declared_monthly_income。
  • 連續登入、深夜比例、下注連敗增加、限額調整次數。

門檻：0-30 無處置、31-50 提醒、51-70 冷卻 30 分鐘、71-85 客服主動聯繫、86-100 強制冷靜期。

5. 定時作業

  • 每日 UTC 02:00：重算 RG 分數。
  • 每週：高分名單給客服系統。
  • session reminder：WebSocket / 前端輪詢每次登入觸發。

6. 前端/UX 規格落地

  • 註冊流程與同意頁必填（不可跳過）。
  • 儲值頁展示「月上限/已使用」進度條，達到 80% 進行軟提醒。
  • RG 區塊頁可調整上限與自我排除。

7. 監管報表

  • 月報：自我排除數、平均分數、強制中斷次數。
  • 季報：介入案件抽樣與改善建議。
  • 年報：有效指標對照與回顧。

8. 驗收

  • 必經 RG 步驟在 E2E 上不可繞過。
  • 提升上限受 cooldown 與風險條件保護。
  • 冷卻與排除在 API 與資料庫層可強制阻擋。
  • 高風險名單自動進客服工單。
