SPEC-020 Analytics & Reporting implementation plan

版本: v0.1.0
更新日: 2026-05-09
對應規格: SPEC-020
目標: 建立一致、可授權、可追溯的分析與匯出能力

1. 資料架構與流程

建議分為三層：事件層、彙總層、匯出層。

  • 事件層：交易事件、帳務事件、客服事件、風險事件保留原始流水。
  • 彙總層：日/小時彙總表與多維度索引（時間、產品、市場、用戶群組）。
  • 匯出層：固定模板與自訂報表以 snapshot 方式輸出。

2. 報表資料模型（實作）

2.1 report_templates

CREATE TABLE report_templates (
  id BIGSERIAL PRIMARY KEY,
  code TEXT NOT NULL UNIQUE,
  name TEXT NOT NULL,
  category TEXT NOT NULL,
  schema_version TEXT NOT NULL,
  definition JSONB NOT NULL,
  created_by BIGINT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  is_active BOOLEAN NOT NULL DEFAULT TRUE
);

2.2 report_jobs

CREATE TABLE report_jobs (
  id BIGSERIAL PRIMARY KEY,
  template_id BIGINT NOT NULL REFERENCES report_templates(id),
  requested_by BIGINT NOT NULL,
  params JSONB NOT NULL DEFAULT '{}',
  state TEXT NOT NULL,
  started_at TIMESTAMPTZ,
  finished_at TIMESTAMPTZ,
  output_uri TEXT,
  output_rows BIGINT,
  row_hash CHAR(64),
  error_message TEXT
);

2.3 report_shares

CREATE TABLE report_shares (
  id BIGSERIAL PRIMARY KEY,
  report_job_id BIGINT NOT NULL REFERENCES report_jobs(id),
  shared_to BIGINT NOT NULL,
  shared_scope TEXT NOT NULL,
  share_type TEXT NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  expires_at TIMESTAMPTZ
);

2.4 report_audit

CREATE TABLE report_audit (
  id BIGSERIAL PRIMARY KEY,
  report_job_id BIGINT NOT NULL REFERENCES report_jobs(id),
  actor_id BIGINT NOT NULL,
  action TEXT NOT NULL,
  action_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  ip INET NOT NULL,
  user_agent TEXT,
  details JSONB NOT NULL DEFAULT '{}'
);

3. 報表權限模型

  • 角色對應報表範圍：營運、客服、風控、財務、法務。
  • 同一角色可見欄位由 template definition 控制。
  • report_jobs 需同時驗證角色、IP、登入 session 一致性。
  • 敏感欄位在輸出層做遮罩處理，明文下載需二次授權。

4. 匯出機制

4.1 格式

  • 支援 CSV、XLSX、JSON 三種格式，預設保留 UTF-8。
  • JSON 額外輸出 schema_version 及 generated_at。
  • CSV 需在文件頭固定輸出版本欄位。

4.2 版本與再產生

  • 匯出參數快照儲存在 report_jobs.params。
  • 任何重跑會保留原紀錄，產生新版 report_job。
  • 每個 job 都有 output_rows 與 row_hash 用於可重放比對。

4.3 自動化排程

  • 每日 KPI、每周營運彙整、每月合規彙總改為排程任務。
  • 排程失敗需寫入告警，並附帶重試機制。

5. 資料一致性

  • 同一 report template 在相同參數下結果可重現。
  • 對帳報表需有來源版本與時間界定。
  • 匯出完成後需完成 hash 驗證，並在 report_audit 記錄。
  • 資料修正事件必須有對應「更正快照」與生效時間。

6. 運維與保留

  • 匯出任務的快取可存 7 天，產出檔案在 90 天後移入低成本儲存。
  • 法規保留報表保留至少 7 年。
  • 報表分享與下載 API 使用率與耗時做監控，超過閥值觸發調整。

7. 風險與例外

  • 報表負載高時自動節流，避免影響交易 API。
  • 超大查詢採資料切片與預先快取。
  • 多租戶欄位分離先以角色與租戶條件實作，避免跨域資料外洩。

8. 依賴與驗收

  • SPEC-002：帳本口徑、資金一致性、ledger 留存指標。
  • SPEC-004：結算、申訴與取消退款報表口徑。
  • SPEC-007：報表指標源。
  • SPEC-013：版控與交付稽核。
  • SPEC-016：支付對帳、refund 與 chargeback 口徑。
  • SPEC-018 實作書：匯出與證據鏈對接。
  1. 3 種格式匯出正常且欄位版本一致。
  2. 角色無權匯出會被拒絕並落日誌。
  3. 可再產生同參數報表並比對 hash 不一致告警。
  4. 報表排程穩定、失敗可重試並可追蹤。
  5. 資料保留與刪除依據策略自動執行。
