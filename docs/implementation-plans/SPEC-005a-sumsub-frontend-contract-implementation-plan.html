SPEC-005a — SumSub 前端整合契約實作計畫

規格參照：SPEC-005a-sumsub-frontend-contract.html · 版本：v0.1.2

1. 實作目的

解耦前端 KYC 流程與供應商實作，將整合入口收斂為可替換的 provider adapter；保證 SumSub / iProov / mock 的生命週期一致。

2. 核心不變式

  • INV-UI-1：前端頁面不得直接 import SumSub SDK，必經 provider layer。
  • INV-UI-2：provider mount/unmount 必須具備可控生命週期與事件回傳。
  • INV-UI-3：adapter chain 只做 client-side 串接，帳號提升結果以 webhook + 後端 API 為唯一真相。
  • INV-UI-4：POST start upgrade 與 server action 不得由 client 傳 user_id。
  • INV-UI-5：retry 上限及 idempotency key 嚴格使用 server-derived key，不可由使用者傳入或重構。
  • INV-UI-6：server action 的唯一可信身份來源是 server-side session / auth context，client input 不得包含 userId、externalUserId、applicantId 或任何可推導 subject 的欄位。

3. 介面定義（ts-sdk）

  • KycIdentityProvider：定義 mount(target, params) 及 unmount 回收。
  • KycSessionEvent：ready、step_changed、submitted、completed、abandoned、error。
  • KycAdapterChain：ordered stages，每 stage 定義 required 與 continueAfterSubmit。

目標檔案路徑：packages/ts-sdk/src/kyc-provider/*.ts。

4. 事件與流程

4.1 State machine（Tier2）

  • idle → initializing → mounting → in_progress → awaiting_webhook → done / failed。
  • submitted 後轉入 awaiting_webhook，除非 chain stage 指定 continueAfterSubmit。
  • error recoverable 顯示重試；non-recoverable 顯示客服 CTA。

4.2 Provider Chain

  • Tier2: 只有 sumsub stage。
  • Tier3: sumsub + iproov（可先提供 manifest 與 stub，不啟用時回退錯誤）。
  • backend 回傳 chain 且以 chain 為主。
  • backend 尚未提供 chain 前，frontend 可由 sdkToken 推導相容 manifest；一旦後端回傳 chain，後端值為 authoritative。

5. CSP / Edge 相容性

  • next.config CSP 新增 SumSub 域名於 script/connect/frame 與 media 限定清單（mock 路徑不需）。
  • 路由 /kyc/tier-2、/kyc/tier-3 必須 "use client"。
  • PoC-B 失敗時提供 Node.js route fallback；保持前端介面相容。

6. Mock 與測試

  • mock provider 5 秒自動 emit submitted，必要時全域 hook 觸發。
  • 所有 SDK 測試覆蓋：mount 時序、error 映射、event 轉換、unsubscribe 釋放。
  • E2E：兩次送出只建立一筆 pending；submitted 後 3-5 分鐘 polling 轉 done。
  • Server action test：client 嘗試傳入不同 user identity 時必須被忽略或拒絕，idempotency key 由 server-derived userId 重建。

7. 視訊與可觀測

  • metrics 命名：proph_kyc_session_started_total、completed、abandoned、error_total、webhook_wait_seconds。
  • log 避免輸出 sdk_token、applicantId、原始 step 字串。

8. 驗收

  • provider 架構可插拔，不會直接 import SumSub/其他 vendor 到頁面元件。
  • Tier 2 flow 成功率與失敗重試行為符合 spec 期待。
  • max retry 限制與可恢復邏輯通過 UI 測試。
  • mock/sumsub 兩種 provider 契約一致。
