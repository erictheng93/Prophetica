SPEC-013 CI/CD & 發佈策略 implementation plan

版本: v0.2.0
更新日: 2026-05-09
對應規格: SPEC-013
目標: 形成可複用、可追溯的 PR 與 Release gate 鏈路

1. 目的與邊界

  • 本文件落地 SPEC-017 bootstrap CI，擴展 prod-targeting gate 與部署前安全檢核。
  • 規格面向「何時可發佈」與「哪層環境可驗證」；本文面向「如何實作 pipeline」。

2. 環境分層（實作）

  • local / dev：只跑最小 lint + 單元測試，允許快速回饋。
  • staging：完整 workflow，含寬鬆告警與 artifact 產物可回溯。
  • prod：需通過 prod-targeting gate（SAST/SCA/image scan/IaC/secret migration/e2e）。

3. 必過門檻（必須 pass 的 gate）

pnpm install --frozen-lockfile
cargo build --workspace --locked
cargo sqlx prepare --check
buf lint / buf breaking / stubs sync
make lint（clippy -D warnings / rustfmt / eslint / prettier）
make test（nextest + turbo test）
cargo deny check
cargo geiger regression
secret scan / SAST / image scan / IaC lint / migration dry-run
  • 任何 gate 失敗不得進入 PR merge gate。
  • prod gate 僅在 PR #1 後續 workflow 中啟動。

4. 路徑與快取

4.1 CI 快取

  • PNPM store、cargo target、cargo registry、sccache 或對應 cloud cache key。
  • workflow 中以 `restore-keys` 設計減少 cold cache 風險。

4.2 Runner 策略

  • 預設 `ubuntu-latest`；若有 `ubuntu-latest-4-cores` 設定再用 larger runner。
  • 未配置 larger runner 時不允許 pipeline 永久卡住於 queued。

5. 不變式

  • 所有發佈路徑必須有可重現輸入（lockfile + sqlx metadata）。
  • prod 佈署前必須執行 secret-scan 與 SCA。
  • migration dry-run 過期或不一致直接阻斷 release。

6. 驗收

  1. 新 PR 依 spec 路徑進入最少 3 種環境驗證（至少 dev/staging/prod-preview）。
  2. SAST/SCA/image scan 報表保留 30 天以上。
  3. CI 導出版本與變更清單可回溯到 PR 編號與門檻結果。
