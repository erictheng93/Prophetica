SPEC-012 customer support implementation plan

版本: v0.1.0
更新日: 2026-05-09
對應規格: SPEC-012
目標: 將客服、SLA、工單、審核與帳本關聯流程轉為工程可落地清單

1. 目的與邊界

  • 規格保留業務語意，本文件收斂客服系統的資料模型、權限、SLA 告警與調度流程。
  • 不在本文件中定義 UI 細節與客服腳本文案；僅保留資料欄位、任務分派、稽核需求。

2. 工程對應

  • §3 工單系統：分類矩陣、SLA、ESCALATE 路由規則
  • §4 權限分級：T1/T2/T3/Admin/Compliance 操作邊界
  • §5 查詢介面：player profile、KYC、交易與 RG 歷史聚合查詢
  • §6 RG 個案：主動關懷觸發、回訪與 4 小時處置節點
  • §11 帳本整合：`compensation` API 與 `audit_logs` 強制留痕

3. 資料模型（建議）

CREATE TABLE support_tickets (
  id BIGSERIAL PRIMARY KEY,
  user_id BIGINT NOT NULL,
  category VARCHAR(32) NOT NULL,
  priority VARCHAR(8) NOT NULL,
  channel VARCHAR(16) NOT NULL,
  assignee_team VARCHAR(16),
  state VARCHAR(16) NOT NULL,
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  sla_due_at TIMESTAMPTZ NOT NULL,
  escalated_at TIMESTAMPTZ,
  resolved_at TIMESTAMPTZ
);

CREATE TABLE support_ticket_events (
  id BIGSERIAL PRIMARY KEY,
  ticket_id BIGINT NOT NULL REFERENCES support_tickets(id) ON DELETE CASCADE,
  event_type VARCHAR(32) NOT NULL,
  actor_user_id BIGINT NOT NULL,
  actor_role VARCHAR(16) NOT NULL,
  payload_json JSONB NOT NULL DEFAULT '{}',
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);
  • `support_tickets.state` 允許：NEW / ASSIGNED / IN_PROGRESS / AWAITING_USER / RESOLVED / CLOSED / ESCALATED。
  • `support_tickets.sla_due_at` 預先計算，並以 SLA worker 驗證 24h/72h 告警。
  • `support_ticket_events` 用於事件溯源與回放稽核。

4. 權限與 API

4.1 RBAC（最小權限）

  • T1：可查詢用戶摘要、回覆工單、調整單筆設定。
  • T2：可回應爭議、KYC 重啟、解凍、執行 RG case。
  • T3：可提案帳本調整、外部回應、提交 SAR。
  • Admin：可改客服設定、FAQ、流程參數。
  • Compliance：簽核與外部監管溝通入口。

4.2 端點（落地建議）

/api/internal/support/tickets
/api/internal/support/tickets/{id}/assign
/api/internal/support/tickets/{id}/transition
/api/internal/support/tickets/{id}/message
/api/internal/support/sla/violations
工程師不應允許客服直接寫入帳本；帳本動作一律走 `compensation` 提案 API 與 4-eye 流程。

5. 不變式

  • 客服系統不得回傳完整 PII（完整身份證號、卡號、明文 hash）給客服前端。
  • `ESCALATED` 需保留原 `ticket_id` 與關聯 evidence；不得刪除。
  • 未滿 24hr 未回應的工單不得被標記 closed，僅可轉入 follow-up 狀態。
  • 親友通報只作為 review input，不得直接作為封禁或停權依據。

6. 工程工作清單

  1. 建 ticket / event / audit 三張表，含必要索引（user_id/state/sla_due_at）。
  2. 實作分派與狀態機轉換（NEW/ASSIGNED/IN_PROGRESS/...）。
  3. 實作 SLA worker：24h 首回覆告警、72h 未解決升級。
  4. 整合 Zendesk/Freshdesk adapter 與本地資料對應表。
  5. 補齊 compensation 提案與 4-eye 簽核串接，綁定 `Txn type = 'cs_compensation'`。

7. 驗收（工程）

  • 工單建立、轉派、升級、關閉流程都有不可變更 audit trail。
  • SLA 告警可在 24hr/72hr 自動觸發。
  • 客服帳號無工程特權前提下，無法直接改帳本。
  • 親友通報與 RG 案件有獨立分流並可產生 follow-up task。
