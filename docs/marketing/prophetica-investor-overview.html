世界每天都在揭曉答案。

撮合模型 · ADR-0001

Order Book + DMM，
而非 AMM／LMSR。

Prophetica 採用訂單簿（Order Book）撮合，並以指定造市商（DMM）提供初期流動性。這是一個刻意的架構決策。

1

平台中立

玩家與玩家、玩家與造市商彼此對手撮合，平台不下場成為交易對手。

2

零資本曝險

平台不持有部位、不承擔賠付，營收來自交易手續費。

3

價格由玩家決定

價格即市場對事件機率的共識，由訂單簿真實供需形成。

4

流動性可成長

第一階段由外部夥伴擔任指定造市商；後續可導入流動性挖礦擴大深度。

相較於由演算法做市的 AMM／LMSR 模型，訂單簿讓平台維持單純的市集營運者角色——只負責上架、撮合與結算，不持有任何一方部位。

商業模式

手續費營收，
代理體系驅動成長。

營收來源

交易手續費

營收來自訂單撮合的手續費。平台不持有部位、不承擔賠付，是一種與交易量同步成長、且資本曝險為零的營收結構。

用戶獲取

多層代理分潤體系（SPEC-011）

以多層級代理分潤推動用戶獲取，讓成長動能來自夥伴網絡，而非單一付費渠道。

入金通路

在地化支付整合（SPEC-016）

整合超商代碼、虛擬帳號、信用卡等在地化通路，降低各市場的入金門檻。

公司架構 · ADR-0002

三公司結構，
清晰的資本與營運分工。

控股、營運、技術三層分立——每一層各司其職，形成乾淨、可向外擴張的組織結構。

控股層

PropheticaNet Holdings

BVI 控股公司，持有智慧財產與股權，作為投資人面對的單一中性主體。

營運層

Operating Co.

持牌司法管轄區
  • 持有營運牌照、面對玩家
  • 簽署服務條款、收取營收
  • 支援未來多牌照擴張
技術層

Tech Service Co.

台灣
  • 聘僱工程團隊、開發軟體
  • 以服務費模式與營運層結算
  • 不直接面對玩家

控股層持有 IP 與股權，營運層持牌經營，技術層專注研發——三者透過明確的合約界面協作，形成對投資人友善、且利於日後跨市場擴張的結構。
